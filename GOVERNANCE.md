# Project Governance

## Maintainer

**icicle** is maintained by [@Eugeneofficial](https://github.com/Eugeneofficial).

## Decision Making

- Technical direction and roadmap are defined by the maintainer
- Community input is welcomed through issues, discussions, and PRs
- Major decisions are announced in release notes and the project roadmap

## Contribution Model

- Fork the repository and submit pull requests
- All PRs require at least one review before merge
- CI must pass (tests, formatting, linting)
- Follow the existing code style and conventions

## Release Process

- Releases are tagged with semantic versioning (`vMAJOR.MINOR.PATCH`)
- Release notes are published in `RELEASE_NOTES_v*.md`
- Binaries are signed and checksums are published with each release
- Changelog is updated in `CHANGELOG.md`

## Communication

- **Bugs**: [Issue Tracker](https://github.com/Eugeneofficial/icicle/issues/new?template=bug_report.yml)
- **Features**: [Feature Request](https://github.com/Eugeneofficial/icicle/issues/new?template=feature_request.yml)
- **Performance**: [Performance Report](https://github.com/Eugeneofficial/icicle/issues/new?template=performance_report.yml)
- **General Discussion**: [GitHub Discussions](https://github.com/Eugeneofficial/icicle/discussions)

## Code of Conduct

All participants are expected to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Security

Security vulnerabilities should be reported privately via the [SECURITY.md](SECURITY.md) process.
